# Executor runtime repair

Use this path when code-mode tools fail before shell startup with `failed to spawn code-mode host`, or Desktop keeps launching an older CLI after a Store update.

1. Inspect the actual Desktop and `codex.exe` process paths, User/Process `CODEX_CLI_PATH`, and `[mcp_servers.node_repl.env].CODEX_CLI_PATH`. A current Desktop package can still launch an older CLI because of a persisted override. Directory timestamps alone do not establish who removed a companion.
2. Run `scripts/install-computer-use-local.ps1 -OnlyExecutorRuntime -StrictVerifyOnly`. The check compares the selected CLI and shipped companions against the current package with full SHA-256 hashes and rejects stale persisted pins. `RestartRequired` describes the caller's inherited override; inspect live processes separately.
3. Run the same command without `-StrictVerifyOnly` to repair. It restores missing companions only beside CLIs matching that exact package. It migrates existing User and node_repl pins only from ordinary `OpenAI\Codex\bin\<16-hex>\codex.exe` paths, keeps absent overrides absent, and rejects custom paths, junctions and existing mismatched companion bytes. `-SkipUserEnvironment` leaves the User override outside this repair. The timestamped environment record and exact config backup under `.codex\backups` support rollback.
4. Preserve an active older runtime until its processes exit. To recover tools in that running process before migration, obtain the older package whose `codex.exe` fully matches the live CLI, then restore its matching missing host. A newer host beside an older CLI is not a verified repair. If the matching package is unavailable, use an independent external terminal to migrate and restart.
5. Save a handoff before restarting Desktop. Use an independently verified process outside Desktop's process tree and Job, follow the existing installer-lifetime rule, and activate the installed AppUserModelId with the updated environment. Inspect the new app-server path, persisted pins, package hashes and a real code-mode shell call after restart. A fixture pass or unchanged running process is not restart acceptance.

Normal local repair and strict plugin verification include this contract. Run `test-codex-executor-runtime.ps1 -TemporaryRoot <task-test-directory>` after changing it; the fixtures cover stale pins, missing and mismatched companions, rollback records, idempotence, absent overrides, custom paths and junctions without changing the real User environment.
